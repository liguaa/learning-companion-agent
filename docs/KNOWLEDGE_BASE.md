# 个人知识库

当前支持本地 Markdown、纯文本资料的导入、更新、删除、检索与来源引用。知识库与学习会话同存于 `DATABASE_PATH` 指定的 SQLite 数据库，使用独立的表；不需要启动数据库服务。

## 快速体验

在 `agent_env` 中执行：

```powershell
python main.py --kb-import examples/knowledge/python_copy.md
python main.py --kb-list
python main.py --kb-search "浅拷贝"
python main.py
```

进入聊天后可以问：“结合我的 Python 笔记，引导我理解浅拷贝为什么会影响嵌套列表。”Agent 会按需调用 `search_knowledge`，根据实际返回片段引用资料，仍遵循逐级提示策略。

## 管理资料

```powershell
python main.py --kb-import "D:\我的笔记\Python 学习.md"
python main.py --kb-import "D:\我的笔记"
python main.py --kb-list
python main.py --kb-search "递归 终止条件"
python main.py --kb-show <资料ID>
python main.py --kb-delete <资料ID>
```

- 支持 `.md`、`.markdown`、`.txt`，单个文件最多 2 MiB；支持 UTF-8、带 BOM 的 UTF-8 与 GB18030。
- 导入目录时递归处理支持的文件，跳过指向目录外的符号链接文件。批量导入按文件独立提交；某个文件失败时会显示失败原因，其他成功文件保留。
- 导入时保存一份资料文本快照，之后原文件变化不会自动同步。对同一个绝对路径重新导入即可更新；内容和索引设置都未变化时不重复导入。
- 更新保留资料 ID，增加版本号，原子替换片段和索引。向量化失败时保留原版本。
- 删除会同时移除文本快照、片段、全文索引和向量；原始文件保留。已在会话中展示过的内容仍属于会话历史，删除资料不等于删除聊天记录。
- 移动文件后导入会作为新来源记录；需要时手动删除旧路径的记录。
- `--kb-list`、`--kb-import`、`--kb-search`、`--kb-show`、`--kb-delete` 在默认全文模式下都不需要模型 Key。

聊天中也可使用 `/kb list`、`/kb import <路径>`、`/kb search <关键词>`、`/kb show <ID>`、`/kb delete <ID>`。路径有空格时可使用引号，Windows 反斜杠会保留。

## 检索方式

### 默认：本地全文检索

```dotenv
KB_SEARCH_MODE=keyword
KB_CHUNK_SIZE=900
KB_CHUNK_OVERLAP=120
```

资料按段落或行边界优先切分，长行按字符长度切分，并保留重叠、章节与行号。全文索引使用 SQLite FTS5 和 BM25，中文使用相邻双字片段及单字索引，英文支持单词和标识符检索。

这属于词项匹配，不具备语义模型的同义词理解能力。查询可以尝试资料中的关键词；Agent 可以换一组关键词再次检索。所有切分和全文检索均在本机进行，不会为建立索引发送笔记给聊天服务。

### 可选：混合语义检索

```dotenv
KB_SEARCH_MODE=hybrid
EMBEDDING_MODEL=你的向量模型名称
EMBEDDING_API_KEY=独立的向量服务密钥
EMBEDDING_BASE_URL=兼容OpenAI的向量服务地址
```

Embedding 配置独立于 DeepSeek/OpenAI 聊天配置；程序不会复用聊天 Key。如果省略向量服务地址，适配器使用 OpenAI 默认 Embedding 地址，因此使用其他服务时应填写正确地址。

混合模式通过 `OpenAIEmbeddings` 生成真实语义向量，将其归一化后存入 SQLite；检索时结合全文召回与余弦相似度召回，使用排名融合排序。当前采用面向小型个人资料库的逐片段向量扫描，大规模资料库后续可替换为专用向量索引。

切换到混合模式、更换向量模型或服务地址后，对相应资料重新导入以建立新向量。缺少当前模型向量的片段会提示重新导入；不同服务或模型的向量不会混用。语义召回的最低余弦相似度为 0.3，并不代表内容必然相关，需结合来源核对。

混合模式会把导入片段和检索问题发送给所配置的 Embedding 服务。自动测试使用确定性的测试向量验证工程行为，真实语义检索效果需要使用你配置的向量服务评估。

## 来源与边界

检索返回 `[KB:资料ID:r版本:c片段]` 引用标记、文件名、章节、行号和原文。回答会提示模型在相关解释处引用，并附加实际工具结果中的“本轮检索资料”；来源列表表示检索到的材料，不保证模型每一句话都由资料支持。

查询最多 256 个字符，一次最多 5 个片段，工具结果总长度限制为 8000 个字符。模型只能检索已导入资料，不能通过该工具读取任意路径、修改文件或运行代码。资料中的指令按数据处理，不授予工具权限；提示词防护仍需在实际使用中持续评估。

没有相关结果时，工具返回空列表，模型应明确说明资料不足。历史检索内容可能已过时，回答当前资料问题时要求重新检索；回复附加的来源会核对当前资料版本。

SQLite、辅助文件和推荐的个人资料目录 `data/knowledge/` 已被 Git 忽略。仓库其他位置的原始文件仍受其各自 Git 规则控制，导入操作不会自动为任意原文件添加忽略规则。知识库本身不执行 GitHub 上传。普通聊天中，实际检索片段会随上下文发给聊天模型服务。

## 验证范围

自动测试覆盖中英文检索、重复导入、版本更新、删除清理、行号、编码、长文本切分、可选向量召回、向量化失败回滚、工具结果长度、实际工具循环和来源归档。

经用户批准，已将自带的 `python_copy.md` 示例用于真实 DeepSeek 验证：模型调用了一次 `search_knowledge`，引用了检索结果中的标记、文件名及第 1～23 行，并提出预测练习。示例已导入正式知识库，测试对话保存在临时数据库；此验证使用默认全文检索，未调用外部 Embedding 服务。

可按以下方式手动验收：导入示例 → 查询浅拷贝 → 修改文件并重新导入 → 核对版本与新内容 → 删除资料 → 确认检索不再返回该资料。真实对话需要同时验证引导方式和引用准确性。
